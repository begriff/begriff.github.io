(Auto-)Stitching Photo Mosaics (Project 3)

Overview

In the first half of this project I demonstrate the use of homographies to warp images. Using homographies, we can rectify shapes in images and produce panorama mosaics. In the second half of the project, I implement a feature-based image stitching algorithm to stitch together sets of images into photo mosaics.

A.3: Warp the Images

Using homographies, we can perform image rectification to take warp rectangles viewed at an angle to rectangles viewed from the front. To sample each pixel in the output rectified image, we compute the inverse homography H^-1 and use the transformed coordinates to sample from the untransformed source image. I implement two ways to sample from the source image: nearest neighbor and bilinear interpolation.

Nearest neighbor sampling just rounds the transformed coordinates to integer values and samples from the source image at those coordinates.

Bilinear interpolation samples by using the transformed coordinates to calculate a weighted average of the 4 closest pixels to determine the value of the pixel in the output image. The weights are determined by the distance from the transformed coordinates to the surrounding pixels. I calculate a weighted average in the y-direction to get 2 average values, and then average these two values in the x-direction to get the final value.

Bilinear interpolation is much more computationally expensive than nearest neighbor since it requires sampling from 4 pixels, and calculating 2 weighted averages (hence bilinear).

The top-left image took 0.51 seconds to rectify and the top-right took 1.41 seconds. The bottom-left took 4.47 seconds and the bottom-right took 11.60 seconds.

A.4: Blend the Images into a Mosaic

I use the images from the sets in A.1 to create a mosaics. For each set, I choose the middle image as a reference image. For the other images, I choose point correspondences between them and the reference. Then, I calculate the homography that maps each image to the reference using the procedure described above. Using the inverse homography matrices, I am able to map pixel coordinates on the output image to pixel coordinates on the source image.

Before I sample, I figure out the dimensions of the output image by simply taking the min and max of the x and y coordinates of the coordinates of all the warped image corners. I then create a blank output image with size determined by the difference between the max and min coordinates. I additionally use the min x and y to compute a translation vector since (0, 0) on the output image does not necessarily correspond to (0, 0) on the reference image.

For each image, I create its own blank output image just for storing image-specific warped pixels for putting it all together later. I then iterate over each pixel in the output image and use the inverse homography to map the pixel coordinates to the source image. I either use nearest neighbor or bilinear interpolation as described above in A.3 and obtain a sample of the source image at the transformed coordinates. I then place the pixel in the output image.

After this, I have a set of per-image outputs to combine. The issue that needs to be handled is that there may be pixels on the final output which correpsond to multiple source images. In fact, there necessarily must be since we define our correspondences by takinga advantage of this overlap between images. Just overwriting one warped image with another is a bad idea since it leads to hard edge artifacts.

In order to combat this, I used cv2.distanceTransform to generate an alpha mask for each image for use in blending. The input to the distance transform is an all-ones array the same size as each image, but with all the edges set to 0. This way, each pixel on the alpha mask is the distance from the edge of the image. I then use the alpha mask values as weights for computing weighted averages of the samples from each image when blending the images together. So, if a transformed pixel is 1 away from the edge of its warped image, it will be weighted and there is a competing pixel from another image 3 away from the edge of its warped image, the first one will be given 25% influence on the average and the second one will be given 75% influence on the average. Note that division by zero needs to be handled by returning 0 in that case.

B.1: Harris Corner Detection

To automatically gather alignment points for computing homographies, I apply a Harris Interest Point Detector to my images for corner detection. To narrow down the amount of corners and select the strongest ones, I apply Adaptive Non-Maximal Suppression (ANMS).

B.2: Feature Descriptor Extraction

At the detected interest points from the last part, I extract 8x8 feature descriptors by taking a 40x40 chunk of the image around each point, applying a low-pass filter, and sampling over the low-passed chunk. I then bias/gain-normalize the output to get the final feature descriptor.

B.3: Feature Matching

To match these extracted feature descriptors between images, I compute the 2-nearest-neighbors of each descriptor for each descriptor in the first image. The 2-NN are from the other image. I then threshold matches by the ratio of the distance to the 1-NN and the distance to the 2-NN. I think I use 0.9 for this threshold since my dataset is poor, but the paper suggests lower values. I obtain pairs by taking the 1-NN for each descriptor satisfying this cutoff.
