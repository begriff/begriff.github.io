A.3: Warp the Images

Using homographies, we can perform image rectification to take warp rectangles viewed at an angle to rectangles viewed from the front. To sample each pixel in the output rectified image, we compute the inverse homography H^-1 and use the transformed coordinates to sample from the untransformed source image. I implement two ways to sample from the source image: nearest neighbor and bilinear interpolation.

A.4: Blend the Images into a Mosaic

I use the images from the sets in A.1 to create a mosaics. For each set, I choose the middle image as a reference image. For the other images, I choose point correspondences between them and the reference. Then, I calculate the homography that maps each image to the reference. Using the inverse homography matrices, I am able to map pixel coordinates on the output image to pixel coordinates on the source image. I then either using nearest neighbor or bilinear interpolation to sample from the source image and place the pixel in the output image.

An issue with just doing this is that there may be pixels on the output which correpsond to multiple source images. Rather, there necessarily must be since we define our correspondences by takinga advantage of this overlap between images. Just overwriting one warped image with another is a bad idea since it leads to hard edge artifacts. In order to combat this, I used cv2.distanceTransform to generate an alpha mask for each image. The input to the distance transform is an all-ones array the same size as each image, but with all the edges set to 0. This way, each pixel on the alpha mask is the distance from the edge of the image, and thus is a value between 0 and 1. I then use the alpha mask values as weights for computing weighted averages of the samples from each image when blending the images together.
